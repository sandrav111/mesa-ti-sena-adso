LA RUTA

De “no funciona” a un caso que se puede resolver.

La mesa de ayuda necesita información accionable. Sigue estos cuatro pasos y evita intercambios innecesarios.

01 Identifica el servicio 02 Describe el contexto 03 Mide el impacto 04 Adjunta evidencia
  1. 01

    ANTES DE ESCRIBIR

    Identifica el servicio

    Indica qué aplicación, equipo o servicio está involucrado. “Correo institucional” ayuda mucho más que “el sistema”.

    ✓Buen inicio: “No puedo ingresar a la plataforma de matrícula desde Chrome.”
    Servicio
  2. 02

    EL CONTEXTO IMPORTA

    Describe qué ocurrió

    Cuenta qué intentabas hacer, qué pasos seguiste y qué resultado obtuviste. Incluye el mensaje de error literal si existe.

    ✓Buen detalle: “Después de seleccionar Ingresar aparece el mensaje ‘sesión expirada’.”
    Contexto
  3. 03

    AYUDA A PRIORIZAR

    Explica el impacto

    Señala cuántas personas están afectadas y si existe una alternativa temporal. El impacto define la prioridad.

    ✓Buen impacto: “Afecta a mi grupo de trabajo; no podemos cargar la entrega y vence hoy.”
    Impacto
  4. 04

    EVIDENCIA ÚTIL

    Adjunta una prueba

    Una captura, la hora del incidente o el nombre del equipo permiten reproducir el caso. Oculta contraseñas y datos sensibles.

    !Recuerda: nunca adjuntes contraseñas, tokens ni información privada.
    Evidencia
✓

LISTA RÁPIDA

Antes de enviar

  • ✓ El servicio está identificado.
  • ✓ El error está descrito con contexto.
  • ✓ El impacto es comprensible.
  • ✓ La evidencia no expone datos sensibles.

EJEMPLO COMPLETO

Así se ve un buen ticket

“Desde las 8:20 a. m. no puedo ingresar a la plataforma de matrícula. Uso Chrome en Windows 11; al seleccionar Ingresar aparece ‘sesión expirada’. El problema afecta únicamente a mi usuario y no tengo una alternativa porque debo cargar la evidencia antes de las 5:00 p. m. Adjunto captura sin datos personales visibles.”
